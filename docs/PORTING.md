# Unity 이식 인수 문서 (울리는 전리품 v2b → Unity 6 LTS 2D)

이 문서만 읽으면 Claude Code가 무엇을, 어떤 순서로, 어디까지 만들면 되는지 알 수 있습니다. 웹 프로토(`reference/v2b.html`)가 규칙 원본이고, Unity는 그 규칙을 그대로 옮기는 것이 목적입니다. 새 규칙을 만들지 않습니다.

## 폴더에 넣을 것
```
(Unity 프로젝트 루트)
├─ CLAUDE.md                      # 아래 "CLAUDE.md에 넣을 요약"을 붙여 넣음
├─ docs/RULES.md, docs/PORTING.md
└─ reference/
   ├─ v2b.html                    # 규칙 원본. LOGIC START~END 블록이 로직 전체
   ├─ golden_maps.json            # 시드 1~20 × 라운드 1·2 기준 배치
   ├─ make_golden.js              # node make_golden.js v2b.html > golden_maps.json
   └─ check_maps.js               # node check_maps.js v2b.html (6000판 검증)
```
`reference/`는 수정하지 않습니다(원본 보관).

## 제출 형태 (공고 조건)
- Unity 결과물은 **영상 또는 로그인 없이 볼 수 있는 WebGL 링크**로만 냅니다. exe·bat·msi 불가.
- 웹 v2b(링크)와 플레이 영상은 Unity가 늦어져도 남는 기본 제출물입니다. Unity는 그 위에 얹는 것입니다.
- 이 작업물에서 Claude가 만든 부분과 본인이 정한 부분은 제출 문서에 구분해서 씁니다(공고: 타인·AI 도움 범위 명시).

## 이식 순서 (앞 단계가 통과해야 다음으로)
1. **프로젝트 뼈대**: Unity 6 LTS 2D(URP 2D), `Assets/Scripts/Core`(UnityEngine 참조 없는 순수 C#), `Assets/Scripts/View`(MonoBehaviour), `Assets/Tests`(EditMode).
2. **시드 난수 + 맵 + 랜덤 배치** (`Core`): `SeededRng`, `FixedMap`, `Zones`, `RandomizeObjects`. **완료 기준: 골든 맵 40개(R1·R2 × 시드 20)와 문자열이 100% 일치하는 EditMode 테스트 통과.** 이게 안 맞으면 이후 규칙이 다 어긋나므로 다음 단계로 가지 않습니다.
3. **플레이어 이동·충돌·카메라**(WASD, 4.2칸/초, 모서리 보정).
4. **횃불·기름·시야**(F, 점등 1초, 반경 3.2, 노출 8초, 기름병).
5. **유물·줍기·던지기·슬롯 UI·점수 배율**(E/클릭 줍기, 우클릭·1/2/3 던지기, 방어 유물).
6. **함정**(경고 1.0 → 작동 0.7, 위험 단계별 주기, 위상 어긋남).
7. **수호자**(상태 기계, BFS 경로, 소리·불빛 반응, 잡기 0.55초). 
8. **붕괴·탈출·결과 화면·로그 복사**.
9. **라운드 2 데이터**(유물 3종·함정 7개·수치), 라운드 전환.
10. **WebGL 빌드와 영상 녹화**, 제출 문서용 스크린샷.
단계마다 하나씩 구현 → 웹 v2b와 같은 시드로 비교 → 다음 단계. 한 번에 여러 시스템을 만들지 않습니다.

## 반드시 지킬 함정 (골든 맵이 어긋나는 흔한 원인)
- **RNG**: JS의 `seededRng`는 mulberry32 변형입니다. `a = (a + 0x6D2B79F5) | 0`, `Math.imul`, `>>>`를 C#에서 `unchecked`와 `uint`/`int` 변환으로 그대로 재현하고, 결과는 `(t ^ (t >>> 14)) >>> 0` 을 4294967296으로 나눈 double입니다. 호출 **횟수와 순서**가 한 번이라도 다르면 이후 배치가 전부 달라집니다.
- **정렬은 안정 정렬**: JS `Array.sort`는 안정 정렬입니다. C# `List.Sort`는 불안정이라 거리가 같은 후보의 순서가 바뀝니다. `OrderBy`(LINQ)를 쓰세요.
- **후보 순서**: 바닥 후보는 행 우선(r 바깥, c 안쪽) 순서로 만들고, 후보에서 뽑을 때는 `splice`처럼 뽑은 원소를 리스트에서 제거합니다.
- **함정 구역 순서**: 라운드 2는 맵을 행→열로 훑으며 처음 만난 구역 순서대로 개수를 소비합니다. 라운드 1은 `trapPlan`의 선언 순서(지름길A → 지름길B).
- **구역 이름 찾기**: `zones` 배열을 앞에서부터 처음 맞는 사각형으로 판정.
- **거리**: 걸음 수는 4방향 BFS, 근접 판정(`near`)은 맨해튼.
- **좌표**: 맵은 `[행][열]`, 월드 좌표는 x=열+0.5, y=행+0.5. Unity는 y가 위로 증가하므로 뷰에서만 뒤집고 Core는 JS 좌표를 유지합니다.
- **수치는 CONFIG에서 복사**: 임의 조정·반올림 금지. 바꾸고 싶은 값이 있으면 코드에 쓰지 말고 아래 "열린 질문"에 적습니다.

## 만들지 말 것 (범위 밖)
3D, 라운드 3, 새 유물·함정, 멀티플레이, 모바일 조작, 기획에 없는 연출. 시간이 남아도 먼저 사람 플레이 확인과 영상을 합니다.

## 완료 기준
- 골든 맵 40개 일치, `check_maps`와 같은 성질(도달 가능·개수·겹침 없음·거리 순서)을 C# 테스트로 3000시드 통과.
- 라운드 1·2를 처음부터 탈출/사망/매몰 결과까지 끊김 없이 플레이 가능.
- 판 끝 로그(이벤트 + 1초 수호자 기록 + 시드)를 복사 가능.
- WebGL 빌드가 로그인 없이 열리고, 3분 이상 플레이 영상 확보.

## 열린 질문 (사람이 정해야 함 — Claude는 임의로 정하지 않음)
- 아트: 웹은 도트 픽셀 스타일입니다. Unity에서 같은 도트를 쓸지, 에셋 출처·이용 조건 `[확인 필요]`.
- 소리: 웹은 합성음입니다. Unity도 같은 방식으로 코드 합성음을 씁니다(제작자 선택, 2026-11-20). `Sfx.cs`가 v2b `Audio_`의 소리 16종과 최소 간격 값을 옮겼고, 외부 효과음 파일은 없습니다. 거리별 크기·발생 조건은 v2b `handleFx`를 따랐습니다. M 키로 켜고 끕니다. 웹 브라우저(WebGL)에서 첫 클릭 전에 소리가 막히는지는 [확인 필요].
- 입력: 웹은 마우스 클릭 줍기입니다. 패드 지원 여부(기본은 지원 안 함).
- 일정: 11/24 23:59 마감까지 단계 6~7을 어디까지 할지.

## v2b와 다르게 하기로 한 것 (제작자 결정, 2026-11-20)
- **유물 줍기는 마우스 좌클릭만, 횃불로 한 번 본 유물만.** v2b의 E 키 줍기(`interact`)는 `rl.seen`을 확인하지 않아 "본 것만 줍는다"는 규칙과 어긋나서 Unity에는 옮기지 않았습니다. 입구 탈출도 좌클릭입니다. 웹 v2b 자체는 고치지 않았고 규칙 원본(`reference/v2b.html`)은 그대로입니다. 이 차이로 웹과 Unity의 같은 시드 비교 결과가 달라질 수 있는 곳은 유물 줍기 입력뿐입니다.

- **마우스 위치는 줍기 클릭과 던지는 방향에만 씁니다 (제작자 결정, 2026-11-20).** 캐릭터는 마우스 조준 방향이 아니라 마지막으로 이동한 방향을 봅니다. v2b는 캐릭터와 횃불이 마우스 조준 방향(`aim`)을 따라 도는데, Unity는 이를 옮기지 않았습니다(`PlayerState.UpdateAim`은 Core에 남아 있고 뷰가 부르지 않습니다). 던지기는 우클릭과 1·2·3 모두 마우스 위치로 던지고, 마우스가 화면 밖이면 바라보는(이동) 방향으로 던집니다. 이 결정은 이전에 구두로 정했다고 하셨으나 기록이 없어서 이번에 적었습니다 `[확인 필요: 이전 결정 내용과 같은지]`. 입구 탈출 입력(좌클릭 유지 여부)은 아직 정하지 않았습니다.
- 판 끝 로그 칸과 "로그 복사" 버튼은 플레이어에게 보이지 않게 합니다(제작자 제안 후 반영, 2026-11-20). 에디터와 Development Build에서만 보이고, 배포용 WebGL 빌드에는 나오지 않습니다. 로그 자체는 계속 기록하며 판이 끝나면 Unity 콘솔에도 출력합니다. 배포 빌드에서 로그를 꺼내야 하면 [확인 필요: 방법]입니다.
