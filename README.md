# 울리는 전리품 (Ringing Loot)

어두운 유적에서 횃불로 유물을 찾아 들고, 수호자를 피해 입구로 돌아와 탈출하는 탑다운 2D 게임입니다. 웹 프로토타입으로 규칙을 먼저 확인한 뒤, 같은 규칙을 Unity 6 LTS(2D, URP 2D)로 옮긴 개인 프로젝트입니다.

## 핵심 재미

유물을 더 들수록 점수 배율이 오르지만(2개 ×1.25, 3개 ×1.5) 발소리가 커지고 수호자가 빨라집니다. **"더 욕심낼까, 나갈까"** 를 고르게 하는 것이 제가 만들고 싶었던 재미입니다. 위험은 밖에서 갑자기 오지 않고 플레이어 행동의 결과로 옵니다. 횃불을 켜면 노출되고, 움직이면 발소리가 나고, 유물을 들면 소음과 속도가 늘어납니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| WASD / 방향키 | 이동 |
| F | 횃불 켜기·끄기 |
| 좌클릭 | 횃불로 본 유물 줍기, 입구에서 탈출 |
| 우클릭, 1·2·3 | 유물 던지기 |
| M | 소리 켜기·끄기 |
| R / N | 결과 화면에서 같은 맵 / 새 맵으로 다시 |

## 저장소 구성

| 위치 | 내용 |
| --- | --- |
| `reference/v2b.html` | 규칙의 원본인 웹 프로토타입(단일 HTML). 문서와 다르면 이 파일이 맞습니다. |
| `reference/golden_maps.json` | 시드 1~20 × 라운드 1·2의 기준 맵 배치. Unity 코드는 같은 시드에서 같은 배치가 나와야 합니다. |
| `Assets/Scripts/Core` | 게임 규칙. MonoBehaviour 없는 순수 C# 클래스입니다. |
| `Assets/Scripts/View` | 화면·입력·효과음. 규칙은 넣지 않은 얇은 뷰입니다. |
| `Assets/Tests/EditMode` | Core 규칙을 에디터 없이 확인하는 EditMode 테스트 |
| `docs/` | 규칙 명세(`RULES.md`), 수치(`CONFIG.json`), 이식 순서와 결정 기록(`PORTING.md`) |
| `CLAUDE.md`, `AI_LOG.md` | AI와 작업할 때의 기준 문서, AI가 한 일과 직접 확인한 일의 기록 |

## 실행과 확인 방법

- Unity 6 LTS 에디터로 이 폴더를 열고 Play를 누르면 라운드 1이 시작됩니다.
- 규칙 테스트: Window > General > Test Runner > EditMode > Run All
- 웹 프로토타입의 맵 성질 검사: `node reference/check_maps.js reference/v2b.html`

## 진행 상태

- Unity 이식은 맵·시드 난수·랜덤 배치, 이동, 횃불, 유물, 함정, 수호자, 붕괴·탈출·결과 화면까지 구현했습니다. 라운드 2는 아직 옮기지 않았습니다.
- Unity에서 직접 확인한 것: EditMode 테스트 73개 통과, Play에서 이동·횃불·유물·수호자·함정 동작과 도트 스프라이트 적용
- 아직 확인하지 못한 것: 효과음의 크기와 겹침, WebGL 빌드, 저 외의 사람이 Unity 판을 플레이해 본 결과입니다. 기름·붕괴 시간 같은 수치는 대부분 제가 정한 초기값입니다.

## AI 활용

방향과 규칙 결정, Unity에서의 실행 확인은 제가 하고, 코드 구현과 테스트 초안은 AI(Claude Code)와 함께 만들었습니다. 이 작업에서 AI는 Unity를 실행하지 않아서, 컴파일·테스트·플레이는 직접 돌리고 결과를 AI에게 전달했습니다. 결정은 `docs/PORTING.md`에, 작업별 "AI가 한 것 / 직접 확인한 것 / 아쉬웠던 것"은 `AI_LOG.md`에 남겼습니다.

## 에셋

도트 스프라이트는 제가 구상한 것을 Claude와 ChatGPT로 구현했습니다. 효과음은 외부 파일 없이 코드로 합성합니다(`Assets/Scripts/View/Sfx.cs`). 에셋별 제작 도구와 참고한 자료의 출처는 정리 중입니다.
